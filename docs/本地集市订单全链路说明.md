# 本地集市订单全链路说明

## 1. 目标与范围

本文档描述当前仓库内“本地集市订单”的完整前后端逻辑，覆盖：

- 用户端：下单、支付、取消、退款、确认收货、查看物流、再来一单
- 商家端：订单列表、订单详情、接单/拒单/发货
- 消息模块：会话列表、历史消息、发送消息、订单会话确保
- 兼容性：旧接口路径与新接口路径并存

## 2. 核心状态机

### 2.1 订单状态 `order_status`

- `pending_payment`：待付款
- `pending_accept`：已付款待商家接单
- `pending_service`：商家备货中
- `pending_receipt`：配送中/待收货
- `completed`：已完成
- `cancelled`：已取消
- `refunded`：已退款

### 2.2 支付状态 `pay_status`

- `unpaid`：未支付
- `paid`：已支付
- `refund_pending`：退款处理中
- `refunded`：已退款

### 2.3 关键状态转换

- 用户创建订单：`pending_payment + unpaid`
- 模拟支付成功：`pending_payment -> pending_accept`，`unpaid -> paid`
- 商家接单：`pending_accept -> pending_service`
- 商家开始配送：`pending_service -> pending_receipt`
- 用户确认收货：`pending_receipt -> completed`
- 用户/商家取消并退款：进入 `cancelled/refunded`

## 3. 数据模型

### 3.1 订单域（新增）

- `MarketOrder` -> 表 `market_orders`
- `MarketOrderItem` -> 表 `market_order_items`
- `MarketRefundOrder` -> 表 `market_refund_orders`
- `MarketCartItem` -> 表 `market_cart_items`

### 3.2 消息域（新增）

- `Conversation` -> 表 `conversations`
- `UserConversation` -> 表 `user_conversations`
- `Message` -> 表 `messages`

### 3.3 自动建表策略

订单与消息控制器在首次请求时会执行 `sync()`，确保本地联调环境可直接运行，无需先手工迁移。

## 4. 后端接口

## 4.1 用户端集市接口（`/api/v1/market`）

- `GET /shops/:shopId/contact`：商家电话
- 购物车：
  - `GET /cart`
  - `POST /cart/items`
  - `PUT /cart/items/:itemId`
  - `DELETE /cart/items/:itemId`
  - `DELETE /cart`
- 订单：
  - `POST /orders/preview`
  - `POST /orders`
  - `GET /orders`
  - `GET /orders/:orderNo`
  - `POST /orders/:orderNo/cancel`
  - `DELETE /orders/:orderNo`
  - `POST /orders/:orderNo/buy-again`
  - `GET /orders/:orderNo/logistics`
- 支付：
  - `POST /payments/create`
  - `GET /payments/status`
  - `POST /payments/mock-success`
- 收货与退款：
  - `POST /orders/:orderNo/confirm-receipt`
  - `POST /orders/:orderNo/refund`
  - `GET /orders/:orderNo/refund`
  - `POST /orders/:orderNo/refund/cancel`

## 4.2 商家接口（`/api/v1/market/merchant`）

- `GET /orders`
- `GET /orders/:orderNo`
- `POST /orders/:orderNo/action`
  - `action=accept`
  - `action=reject`
  - `action=dispatch`
  - `action=delivered`
- `GET /payments`

## 4.3 消息接口

主路径（单数）：

- `/api/v1/message/conversations`
- `/api/v1/message/history/:conversationId`
- `/api/v1/message/conversations/:conversationId` (DELETE)
- `/api/v1/message/send`
- `/api/v1/message/order-conversation/ensure`
- `/api/v1/message/broadcast`

兼容路径（复数）：

- `/api/v1/messages/*` 与上述接口等价

## 5. 兼容性与历史路径

为兼容旧前端调用，保留以下别名：

- `POST /api/v1/market/order/create` -> 复用创建订单
- `GET /api/v1/market/orders/my` -> 复用订单列表
- `GET /api/v1/messages/*` -> 复用 `/message/*`

商家订单动作兼容：

- `/orders/:orderNo/accept`
- `/orders/:orderNo/cancel`
- `/orders/:orderNo/ship`
- `/orders/:orderNo/complete-delivery`

均会转为统一 `orderAction`。

## 6. 前端关键页面与调用关系

- 订单确认页：`pages/goods-confrim/goods-confrim.js`
  - 预结算：`api.market.previewOrder`
  - 下单：`api.market.createOrder`（含 `market/order/create` fallback）
- 订单列表页：`pages/market-order-list/market-order-list.js`
  - 列表：`api.market.getMyOrders`
  - 操作：取消/支付/退款/确认收货/删除/再来一单
- 订单详情页：`pages/market-order-detail/market-order-detail.js`
  - 详情：`api.market.getOrderDetail`
  - 操作同上，并可进入聊天或电话联系

## 7. 已修复的高风险点

- 后端 `market` 订单主链路 501：已替换为可运行逻辑
- 后端 `merchant` 订单动作 501：已替换为可运行逻辑
- 后端 `message` 501：已替换为可运行逻辑并补齐订单会话确保接口
- `/message` 与 `/messages` 路径不一致：已加复数兼容路由
- `market-order-detail` 首屏变量引用错误：已修复（移除未定义变量访问）
- 状态映射不一致：已补充 `paid/delivering/closed` 等别名映射

## 8. 联调建议

- 本地先验证顺序：
  1. 下单 -> 模拟支付成功 -> 订单进入待接单
  2. 商家接单 -> 开始配送 -> 用户确认收货
  3. 用户申请退款 -> 商家拒单退款分支
  4. 消息会话创建与消息发送
- 若你连接 110.50 主后端，建议保持本地路径兼容配置，避免环境切换导致 404。
