## 1. 文档目标

- 先明确“集市商家工作台”每个按钮的功能需求与最小数据需求。
- 再梳理当前前端已接入/未接入接口，不先强行约定最终接口路径。
- 给后端同事一份可逐条确认的清单：哪些接口已实现、哪些需新增、哪些会涉及数据库增删改查与字段补充。

## 2. 范围说明

本次覆盖页面入口：`package-market/pages/market-home/market-home`（集市商家工作台）。

覆盖按钮（按页面顺序）：
1. 店铺入驻与资质
2. 商品与库存
3. 集市订单
4. 店铺预览
5. 资金与对账
6. 店铺设置
7. 商品上下架（上架管理 / 下架管理）

## 3. 功能需求总览（前端视角）

## 3.1 店铺入驻与资质

点进去应看到已提交/已审核的店铺信息（可参考后端管理页）：

- 基础：店铺名、类目、联系人、联系电话、详细地址、商家简介、申请时间
- 资质：主体名称、法人/经营者、统一社会信用代码
- 推广信息：推广员 ID、推广员姓名
- 图片：
  - 固定三图：`logo_url`、`background_url`、`license_url`
  - 额外实地照：`place_photo_url`（2~5 张）

---

## 3.2 商品与库存

需要支持：

- 商品分类管理：分类新增/编辑/删除/排序
- 商品管理：商品新增/编辑/删除/详情查询
- 库存与价格：补货、库存调整、改价
- 上下架：对单个商品执行上架/下架

商品新增/编辑至少涉及字段（待后端确认最终版）：

- `name`
- `category_id` 或 `category_key`
- `price`
- `origin_price`（可选）
- `stock`
- `safe_stock`
- `description`
- `main_image`
- `images`（可选）
- `sort_order`（可选）
- `status`（on_sale/off_sale）

## 3.3 集市订单

展示本店铺买家订单，包含状态：

- 全部
- 待付款
- 待接单
- 备货中
- 待收货
- 已完成
- 已取消
- 已退款

关键动作：

- 待接单订单点击“接单”后，商家订单状态应更新，且买家端订单状态同步变化。

## 4. 接口需求清单（先列需求，不先锁定最终口径）

状态说明：
- `已实现(前端已调用)`：当前页面或相关页已在调用
- `待后端确认`：可能已有接口，但路径/字段不确定
- `待新增`：目前前端未发现稳定可用接口

## 4.1 店铺入驻与资质

1) 查询店铺入驻详情（当前商家）
- 目的：回显“店铺入驻与资质”全部字段
- 建议接口：`GET /market/merchant/shop`（或同义路径）
- 状态：`待后端确认`
- 最小响应字段：
  - `shop_id`
  - `shop_name`
  - `category`
  - `contact_name`
  - `phone`
  - `entity_name`
  - `legal_person`
  - `credit_code`
  - `promoter_id`
  - `promoter_name`
  - `applied_at`
  - `address`
  - `description`
  - `logo_url`
  - `background_url`
  - `license_url`
  - `place_photo_url[]`
  - `community_id`

2) 更新入驻资料（店铺设置复用）
- 目的：修改联系人/电话/简介/小区 ID（及后续扩展字段）
- 建议接口：`PATCH /market/merchant/shop`
- 状态：`待后端确认`
- 最小请求字段：
  - `contact_name`
  - `phone`
  - `description`
  - `community_id`

3) 图片上传
- 目的：上传 logo/background/license/实地照
- 当前接口：`POST /upload`（已改统一返回规范）
- 状态：`已实现(前端已调用)`（页面通过 `util.uploadFile('upload',...)`）

## 4.2 商品与库存 + 商品上下架

1) 分类列表

2) 分类新增
- 建议：`POST /market/merchant/categories`

3) 分类更新

4) 分类删除

5) 商品列表（支持 mode=up/down）

11) 补货/库存调整

## 4.3 集市订单

1) 订单列表（按状态过滤）
- 当前接口：`GET /market/merchant/orders`（fallback `/market/shop/orders`）

  - `goods_amount`

  - `discount_amount`
  - `payable_amount`
  - `created_at`
  - `items[]`

2) 订单详情
- 当前接口：`GET /market/merchant/orders/:orderNo`（详情页兼容）
- 状态：`待后端确认`

3) 接单（重点）
- 当前调用：`POST /market/merchant/orders/:orderNo/accept`
- 状态：`已实现(前端已调用)`，**需后端确认买家侧状态同步**
- 期望：
  - 商家端：`pending_accept -> pending_service`
  - 买家端：同步为备货中/商家已接单

4) 取消订单
- 当前调用：`POST /market/merchant/orders/:orderNo/cancel`
- 状态：`已实现(前端已调用)`

5) 发货
- 当前调用：`POST /market/merchant/orders/:orderNo/ship`
- 状态：`已实现(前端已调用)`

6) 售后处理（退款）

## 6. 后端确认清单（状态版）

1) `[已确认]` 店铺入驻详情查询  
- 最终标准接口：`GET /api/v1/market/merchant/application`。  
- 返回：`data.application`（无记录时 `application=null`）。  
- `place_photo_url` 统一为 `string[]`，按上传顺序返回。  

2) `[部分确认]` 店铺设置修改（`PATCH /market/merchant/shop`）  
- 已支持并建议前端使用白名单字段：`contact_name`、`phone`、`description`。  
- 后端映射：`phone -> contact_phone`、`description -> notice`。  
- `community_id` 当前为“已受理但暂不落库”：传入时返回 `400` 提示“暂不支持修改，请走入驻信息变更流程”。  
- 待迁移项：若业务确认必须可编辑 `community_id`，需新增库表字段与数据迁移方案。  

3) `[待确认]` 商品分类 CRUD  
- 当前本次联调范围内未新增“商家侧分类 CRUD”接口。  
- 需前后端单独确认是否复用现有分类体系，或新增商家侧分类管理路径。  

4) `[部分确认]` 商品删除接口（硬删/软删）  
- 现阶段商家侧建议走“软下架”（`status=off_sale`）。  
- 硬删策略未作为当前联调必选项，待业务与风控确认后再开放。  

5) `[已确认]` 商品上下架字段口径  
- 后端兼容 `published` 与 `is_published` 入参。  
- 对外状态仍以 `status`（`on_sale/off_sale`）为最终落库语义。  

6) `[已确认]` 订单“接单”后买家端状态同步  
- 商家执行接单动作后：`pending_accept -> pending_service`。  
- 后续发货：`pending_service -> pending_receipt`。  
- 该状态变更写入统一订单状态，可被买家端订单查询实时感知。  

7) `[已确认]` 店铺预览场景的稳定 `shop_id` 来源  
- 权威来源：`GET /api/v1/user/profile`。  
- 当 `merchant_status=approved` 时，`shop_id` 稳定返回；前端据此直达预览页。  

8) `[部分确认]` 资金与对账口径  
- 当前建议先复用现有商家资金相关查询链路（含 `GET /api/v1/market/merchant/payments`）。  
- 是否新增“商家对账专用接口”待本轮工作台主链路稳定后再评估拆分。

### 2026-04-29 05:12 [后端]
- 问题：前端在 `05:10` 回传中反馈：`/market/merchant/application` 与 `/market/merchant/shop` 使用用户 token 访问时返回 `403 非商户令牌`，需后端对“放开用户 token”与“提供换 token 正式接口”二选一拍板。

- 代码改动：  
  1) `backend/src/controllers/merchantPortalController.js` 新增 `exchangeToken`；
