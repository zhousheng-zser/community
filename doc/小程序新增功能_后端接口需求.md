# 小程序新增功能 — 后端接口与数据需求

> **文档性质**：与近期小程序端新增页面/能力（「我的」订单入口、设置隐私、消息通知 Tab、商城搜索、社区公告、钱包明细等）对应，说明 **需后端实现或对接的接口与字段**。  
> **前缀**：除特别说明外，路径均相对 `https://<域名>/api/v1`，请求头需 `Authorization: Bearer <token>`（与现有 `utils/util.js` 一致）。  
> **响应约定**：推荐统一 `{ "errno": 0, "errmsg": "ok", "data": ... }`；列表类支持 `unwrapList`：`data` 为数组，或 `data.list` / `data.items`。

**版本**：v1 · 2026-04-20  

---

## 1. 总原则

| 类别 | 说明 |
|------|------|
| **当前实现** | 部分能力仅写 **本机 Storage**（`utils/localPrefs.js`），无后端时仍可展示。 |
| **上线要求** | 隐私、通知偏好、系统通知、公告已读、诉求单、订单列表等 **应以服务端为权威**，小程序在登录后 **拉取覆盖本地** 或 **读写 API**。 |
| **幂等与审计** | 提现、退款、诉求状态变更需可追溯（操作者、时间、单号）。 |

---

## 2. 用户偏好与隐私（替代/增强本地 Storage）

前端页面：`privacy-publish`、`privacy-reply`、`notification-settings`。

| 能力 | 建议接口 | 说明 |
|------|----------|------|
| 拉取偏好 | `GET /user/preferences` 或合并入 `GET /user/profile` | 返回 `publish_visibility`、`reply_visibility`、`notify`（见下） |
| 更新偏好 | `PATCH /user/preferences` | Body 示例：`{ "publish_visibility": "all\|followers\|self", "reply_visibility": "...", "notify": { "order": true, "system": true, "marketing": true } }` |
| 枚举 | — | 与前端 `visibilityOptions` 一致：`all`、`followers`、`self` |

**验收**：修改后在其它设备登录同一账号可见一致配置。

---

## 3. 惠民卡订单

**前端调用**：`GET benefit/orders?page=1&limit=50`（`pages/benefit-orders/benefit-orders.js`）。

| 项 | 说明 |
|----|------|
| **需实现** | `GET /api/v1/benefit/orders`（若惠民业务挂在别的前缀，请网关转发到同一路径或改小程序 `util` 路径） |
| **Query** | `page`、`limit` |
| **列表项（建议）** | `id`、`order_no`、`title` 或商品名、`status` / `status_text`、`amount`、`created_at` |
| **空列表** | HTTP 200 + `errno:0` + 空数组即可，勿返回 404 作为常态 |

---

## 4. 推客订单

**前端调用**：`GET promoter/orders?page=1&limit=100&status=<tab>`（`pages/promoter-orders/promoter-orders.js`）。

| 项 | 说明 |
|----|------|
| **需实现** | `GET /api/v1/promoter/orders` |
| **Query · status** | 与前端 Tab 对应：`all`（或不传）、`pending`（待结算）、`done`（已结算）；若内部枚举不同，请网关映射 |
| **列表项（建议）** | `id`、`order_no` 或业务单号、`title` / `goods_name`、`commission` 或 `estimated`（预估佣金）、`status` |
| **关联** | 与现有 `api/acount/info`、推客提现、佣金结算规则一致 |

---

## 5. 组合套餐订单（占位）

**前端**：`combo-orders` 页为说明页，未强制请求接口。

| 项 | 说明 |
|----|------|
| **建议** | 若业务上线「套餐 SKU」：`GET /combo/orders` 或与购物订单统一模型加 `type=combo` 筛选 |
| **优先级** | 按产品排期，可与 **购物订单** 合并设计 |

## 6. 用户诉求（申诉）

**前端**：`appeal-list` 当前仅 **本机存储**。

| 项 | 说明 |
|----|------|
| **需实现** | `POST /user/appeals`：Body `{ "content": "文本" }`；可选 `images[]` |
| **列表** | `GET /user/appeals?page&limit` |
| **项字段（建议）** | `id`、`content`、`status`（已提交/受理中/已结案）、`created_at`、`reply`（运营回复） |
| **验收** | 小程序改为登录后拉列表 + 提交走 API；未登录可禁止提交或仅本地草稿 |

---

## 7. 系统通知（消息 Tab ·「通知」）

**前端**：`message` 页「通知」Tab 当前使用 **本地 `system_notices` + seed**。

| 项 | 说明 |
|----|------|
| **需实现** | `GET /user/notifications?type=system&page&limit` 或与消息中心合并 |
| **项字段（建议）** | `id`、`title`、`content`、`read`（boolean）、`created_at` |
| **已读** | `PATCH /user/notifications/:id/read` 或 `POST /user/notifications/read-all` |
| **推送** | 订单状态、审核结果、活动等与现有模板消息/订阅消息策略对齐 |

**验收**：新通知到达后列表与红点与后端一致；换机登录可见历史。

## 8. 社区公告

**前端**：`community` 顶部公告条 +「一键已读」当前为 **写本地已读 Map**。

| 项 | 说明 |
|----|------|
| **需实现** | `GET /community/announcements`：返回 `id`、`title`、`content`（可选）、`priority`、`published_at` |
| **已读** | `POST /community/announcements/read-all` 或逐条 `POST .../:id/read`（按用户维度） |
| **权限** | 仅登录用户或按小区维度，与产品一致 |

**验收**：运营后台发公告后，小程序拉取展示；已读状态跨设备一致。

## 9. 商城搜索（关键词）

**前端**：`shopping-search` 在 **有 `shopId`** 时请求店铺商品；**无 `shopId`** 时请求全站商品列表并带 `keyword`。

| 已调用路径（需后端支持或确认） | 说明 |
|--------------------------------|------|
| `GET market/merchant/goods` | Query：`keyword`、`page`、`limit`，可选 `shop_id` |
| `GET market/shop/goods` | 同上（降级路径） |
| `GET market/shop/:id/goods` | 店内搜索（若已实现） |

**要求**：对 `keyword` 做 **商品名称/简称** 索引查询；返回结构与现有 `merchant-goods` 列表项兼容（`id`、`title`/`name`、`price`、`main_image`/`image` 等）。

## 12. 客服与管家（配置类）

**前端**：`community-steward`、`platform-kefu` 使用 **写死占位热线** + `button open-type="contact"`。

| 项 | 说明 |
|----|------|
| **建议** | `GET /config/support` 返回 `steward_phone`、`platform_phone`、`customer_service_url`（或企业微信参数） |
| **小程序** | 微信客服需在公众平台配置 **客服** 与 **企业客服** 组件；`open-type="contact"` 依赖后台绑定 |

---

## 13. 与现有接口的衔接说明

- **用户资料**：`GET user/profile` 若已存在，建议 **合并** 第 2 节偏好字段，减少请求次数。  
- **集市商品**：`market/merchant/goods` 等已在前端使用，搜索仅增加 **`keyword` 查询参数** 的语义要求。  
- **消息会话**：`messages/*` 不变；系统通知与 **会话列表** 业务上分离，避免混在 `conversations` 中 unless 产品统一「消息中心」。

---

## 14. 优先级建议（供排期）

| 优先级 | 模块 |
|--------|------|
| P0 | `benefit/orders`、`promoter/orders`、钱包交易明细 `GET`、用户偏好 `GET/PATCH` |
| P1 | 系统通知 `GET` + 已读、社区公告 `GET` + 已读 |
| P2 | 诉求 `POST/GET`、客服配置 `GET`、浏览足迹同步 |
| P3 | 组合套餐订单独立接口（或与订单合并建模） |
