# 惠民卡 · 京东 / 拼多多联盟：数据库与同步说明

本文描述当前「惠民卡」Tab 内**京东联盟**与**拼多多**的数据来源、表结构、种子与素材同步流程，以及与小程序的约定。**商品文案、主图路径、推广链、顶栏头图均以数据库为准**；小程序仅保留本地兜底（头图用 `utils/images.js` 中的静态路径、列表为空时不展示商品）。

---

## 1. 架构原则

| 内容 | 存储位置 | 说明 |
|------|----------|------|
| 京东商品列表 | `jd_benefit_goods` | 每条含 `sku_id`（京挑客短链 path）、标题、`image_url`、`spread_url` 等 |
| 拼多多商品列表 | `pdd_benefit_goods` | 每条含 `link_key`（推广 URL 路径段）、标题、`image_url`、`spread_url`、`coupon_price` 等 |
| 顶栏横幅与可选文案 | `benefit_alliance_config` | 按 `scene` + `platform`（`jd` / `pdd`）各一行，含 `hero_image_url`、可选 `hero_title` / `hero_subtitle` |
| 小图标、通用插画 | 小程序本地 `img/`、`utils/images.js` | 不写入上述业务表 |

接口与小程序行为：

- `GET /api/v1/benefit/display?scene=benefit_card`：返回 `jd` / `pdd` 的 `heroImage`、`heroTitle`、`heroSubtitle`（后两者可为空，空则小程序用 WXML 默认文案）。
- `GET /api/v1/jd/benefit/goods?scene=benefit_card`：京东商品列表。
- `GET /api/v1/pdd/benefit/goods?scene=benefit_card`：拼多多商品列表。

`image_url` / `hero_image_url` 推荐存**小程序包内相对路径**（如 `/img/jd_benefit/c64wRk8.png`），与仓库 `img/` 目录一致；若改为 CDN，可存完整 `https://` URL，小程序直接使用。

## 2. 数据表概要

### 2.1 `jd_benefit_goods`

- **sku_id**：与 `https://u.jd.com/{sku_id}` 中路径段一致，用于京挑客 `proxy` 跳转，**不是**京东开放平台数字 SKU。
- **image_url**：列表主图。
- **spread_url**：推广链接（通常即 `u.jd.com` 完整 URL）。

建表脚本：`backend/sql/jd_benefit_goods.sql`。

### 2.2 `pdd_benefit_goods`

- **link_key**：与 `https://p.pinduoduo.com/{link_key}?...` 路径段一致，用于 upsert 与运营对照文档。
- **goods_id**：可选；多多进宝若返回微信路径可与 `mini_path` 配合。
- **coupon_price**：券后价展示。

建表脚本：`backend/sql/pdd_benefit_goods.sql`。

### 2.3 `benefit_alliance_config`

- **scene**：默认 `benefit_card`，与小程序请求参数一致。
- **platform**：`jd` 或 `pdd`（小写）。
- **hero_image_url**：顶栏大图，例如 `/img/benefit_alliance/jd-alliance.png`。
- **hero_title / hero_subtitle**：可选；为空时小程序使用页面内写死的默认副文案。

建表脚本：`backend/sql/benefit_alliance_config.sql`。

## 3. 本地素材与仓库内图片（非数据库二进制）

数据库只存**路径或 URL**，图片文件仍在仓库中维护：

| 模块 | 文档与映射 | 同步脚本 | 生成目录 |
|------|------------|----------|----------|
| 京东商品主图 | `流量联盟/jd_local_images.json` ↔ `京东联盟.md` | `npm run sync:jd-benefit-images`（项目根） | `img/jd_benefit/{sku_id}.png` |
| 拼多多商品主图 | `流量联盟/pdd_local_images.json` ↔ `拼多多.md` | `npm run sync:pdd-benefit-images`（项目根） | `img/pdd_benefit/{link_key}.jpeg` |
| 联盟顶栏设计稿 | `流量联盟/京东联盟.png`、`流量联盟/拼多多.png` | 手动或脚本复制到 `img/benefit_alliance/jd-alliance.png`、`pdd-alliance.png` | 与 `seed-benefit-alliance-config` 中路径一致 |

更新设计稿后：覆盖 `img/benefit_alliance/` 下文件即可；若路径变更，需改库中 `benefit_alliance_config.hero_image_url` 或重新执行联盟配置种子。

## 4. 灌库与一键同步命令

**方式 A：SQL 文件（不依赖 Node 连库密码配置）**

在已创建数据库 `community`（或你的库名）后执行：

```bash
mysql -u root -p community < backend/sql/seed_benefit_bootstrap.sql
```

该脚本会 `CREATE TABLE IF NOT EXISTS` 三张惠民卡相关表，并 `INSERT ... ON DUPLICATE KEY UPDATE` 写入与种子脚本一致的京东 8 条、拼多多 8 条、联盟顶栏 2 条。

**方式 B：Node 种子（需在 `backend/.env` 填写 `DB_HOST`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`）**

在 **`backend` 目录**执行：

```bash
# 仅京东商品
npm run seed:jd-benefit

# 仅拼多多商品
npm run seed:pdd-benefit

# 仅联盟顶栏（头图 URL + 可选文案）
npm run seed:benefit-alliance-config

# 一键：京东 + 拼多多 + 联盟顶栏
npm run seed:benefit
```

首次建表可执行 `backend/sql/` 下对应 SQL，或开发环境设置：

- `DB_SYNC_JD=1`：同步 `jd_benefit_goods` 模型
- `DB_SYNC_PDD=1`：同步 `pdd_benefit_goods` 模型
- `DB_SYNC_BENEFIT=1`：同步 `benefit_alliance_config` 模型  

然后重启 `node backend/src/index.js`（或 `npm run dev`）。

## 5. 小程序侧约定

- 首页 `init` 中依次请求：`benefit/display`、`jd/benefit/goods`、`pdd/benefit/goods`。
- **不再内置**长列表兜底商品数据；接口失败或为空时列表为空，顶栏图仍可用 `utils/images.js` 的 `benefitJdAllianceHero` / `benefitPddAllianceHero` 兜底。
- 底部「GO」京东入口使用列表首条的 `skuId` / `spreadUrl`；无商品时为空，点击会提示缺少信息。

---

## 6. 与流量联盟文档的对应关系

- 京东：`流量联盟/京东联盟.md` 与 `流量联盟/jd_local_images.json` 应与 `jd_benefit_goods` 顺序、sku、标题一致。
- 拼多多：`流量联盟/拼多多.md` 与 `流量联盟/pdd_local_images.json` 应与 `pdd_benefit_goods` 一致。

运营改文档后：更新种子或管理端（若有）→ 执行对应 `seed` → 小程序拉接口即可，无需改前端业务代码。
