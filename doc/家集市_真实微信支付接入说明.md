# 家集市：真实微信支付接入说明

## 1. 目标

家集市下单后的支付流程**仅走微信小程序真实收银台**（`wx.requestPayment`），不再依赖「无 JSAPI 参数时纯轮询等待模拟回调」的旧联调方式。

## 2. 前端行为（已实现）

1. 调用 `POST /api/v1/market/payments/create`，请求体：`{ "order_no": "<订单号>" }`。
2. 若返回 `code !== 0`：提示 `msg`，并跳转订单详情（便于用户继续支付或取消）。
3. **临时虚拟支付**（与 `API_DOC.md` **12.4** 一致）：若 `virtual_pay === true`，或 `pay_mode` 为 `virtual` / `mock`：
   - **不调用** `wx.requestPayment`（占位五参无法调起真实收银台）。
   - 提示「开发联调：虚拟支付（未调起微信收银台）」，并**轮询** `GET /api/v1/market/payments/status` 直至确认已支付或超时，再按配置跳转/刷新订单详情。
4. **真实支付**（`virtual_pay === false` 且非上述虚拟模式）：从响应中解析 **微信 JSAPI 调起参数**（见下节），调用 `wx.requestPayment`。
5. 用户在微信支付弹窗完成支付后：
   - `success`：轮询 `GET /api/v1/market/payments/status` 确认服务端已记账，再进订单详情。
   - `fail`：仍轮询一次（防止回调先到、弹窗失败等边界情况），再进订单详情。

### 2.1 前端识别的支付参数字段

以下任一嵌套对象中，需同时包含：`timeStamp`、`nonceStr`、`package`（形如 `prepay_id=...`）、`signType`、`paySign`：

- `pay_params`
- `wx_pay_params`
- `jsapi_params` / `jsapi`
- `wx_pay`
- 或直接平铺在 `data` 根上

字段名兼容蛇形：`time_stamp`、`nonce_str`、`sign_type`、`pay_sign`。

## 3. 后端必须满足（请后端同事配置）

1. **`payments/create` 返回真实 JSAPI 参数**  
   使用微信支付 **V3**（或贵司统一封装）下单后，将小程序调起支付所需字段返回给前端（与微信文档一致）。

2. **支付结果以服务端为准**  
   配置并验证 **`POST /api/v1/market/pay/callback`**（或贵司约定路径）：验签、幂等、更新 `market_orders` / `market_pay_transactions` 状态。

3. **不再依赖「无参数 + 轮询」完成支付**  
   旧虚拟联调若仅创建交易单而不返回 JSAPI，前端将提示错误并进入订单详情，而不会长时间假轮询。

4. **联调辅助接口**（如 `POST /api/v1/market/payments/mock-success`）  
   仅用于开发/测试环境；生产应禁用。与真实支付互斥，勿作为正式链路。

5. **虚拟模式开关**  
   无商户配置时由后端决定是否返回 `virtual_pay: true`；上线前补齐 `WX_*` 并建议 `MARKET_PAY_VIRTUAL_SUCCESS=false`（见 API_DOC 12.4）。

## 4. 验证清单

| 步骤 | 预期 |
|------|------|
| 创建订单 | 返回 `order_no` |
| `payments/create` | 真支付：`code === 0` 且 `virtual_pay:false`，含可用 JSAPI 五参数 |
| 小程序调起支付 | 真支付时出现微信官方支付界面；虚拟模式不出现（仅轮询状态） |
| 支付完成 | `payments/status` 中 `pay_status` 等为已支付；订单详情一致 |
| 取消支付 | 订单仍为待支付，可再次从订单详情发起支付（若后端提供「继续支付」接口则后续可做） |

## 5. 约定

- 金额 **0 元** 是否免支付：由产品/后端决定；若需免支付，后端应在下单或 `payments/create` 中明确约定，前端再单独分支处理（当前未默认跳过支付）。
