# 内层「首页」样例数据包与数据库映射说明

> **目的**：后续版本以**真实接口 + 数据库**为准；将原先写在前端的假数据**落库**，并在本仓库打包 JSON/SQL 样例，标明 **前端字段 ↔ 数据文件 ↔ 表字段 ↔ API** 的对应关系。  
> **接口契约、表字段级 DDL 建议、后端 JOIN/审核关系**：见 `doc/首页与我的_服务域前后端联调需求.md` **第十一～十三章**。  
> **样例数据物理目录**：`backend/seed-data/home-inner/`（与 `backend/seed_service_groups.js` 同级相对路径可读）。

---

## 1. 总览表

| 小程序模块 | 前端原位置 | 样例包文件 | 主数据库表（约定） | 主要 API |
|------------|------------|------------|-------------------|----------|
| 九类服务落地页 | `tidy-service.js` → `getPageConfig` + 接口 | `service_groups_extra.json` + `seed_service_groups.js` 内建三组 | `Categories`（`group_type`）+ `Services` | `GET /api/v1/core/service-groups/:key` |

## 2. 服务分组（九大类）详细映射

### 2.1 `group_type` / URL `key` 约定

| URL 参数 `key` | JSON / 种子脚本中的分组键 | 前端 `tidy-service` 页标题 |
|----------------|---------------------------|------------------------------|
| tidy | tidy（内建于 `seed_service_groups.js`） | 整理收纳 |
| urgent_fix | urgent_fix（内建） | 家修急事 |
| beauty_home | beauty_home（内建） | 上门美业 |
| appliance_clean | appliance_clean（**extra**） | 家电清洗 |
| pioneer_clean | pioneer_clean | 开荒保洁 |
| mite_remove | mite_remove | 除螨服务 |
| furniture_care | furniture_care | 家具养护 |
| baby_home | baby_home | 宝宝家事 |
| house_repair | house_repair | 房屋修缮 |

### 2.2 表字段映射（`seed_service_groups.js` 写入逻辑）

| JSON 路径 | `Categories` 字段 | `Services` 字段 |
|-----------|-------------------|------------------|
| `categories[].name` | `name` | — |
| `categories[].icon_url` | `icon_url` | — |
| `categories[].sort_order` | `sort_order` | — |
| 分组键 | `group_type` | — |
| `services[].cat` | 用于解析 `category_id`（同组同名类） | `category_id` |
| `services[].title` | — | `title`、`description`（当前脚本 description=title） |
| `services[].price` | — | `price`（decimal） |
| `services[].img` | — | `cover_image` |
| `services[].sales_count_hint`（可选） | — | `sales_count`（插入或更新时写入，**用于 `services/hot` 排序**） |

### 2.3 与前端 `getPageConfig` 的对应关系

- `pages/tidy-service/tidy-service.js` 中 **本地兜底** 的 `categories[]`（字符串数组）↔ 种子里的 **`categories[].name`**。
- 本地 `services[].id`（1～86）为**演示用 ID**；**落库后以数据库自增 `Services.id` 为准**。联调时请将 `config.useCuratedHomeHotList` 设为 `false`，热卖榜完全跟接口 ID，避免写死 73～77 与库不一致。
- 本地 `price` 文案如 `196元/份` ↔ 库内 **`price` 数值 `196`** + 前端按 `priceUnit` 拼单位（单位可后续放 `Services` 扩展字段或分组配置表）。

## 3. 小区热卖榜写死数据 ↔ `Services`

| 前端写死 `hotList.name`（节选） | `service_groups_extra.json` 中 `title`（house_repair） | `sales_count_hint` |
|--------------------------------|--------------------------------------------------------|--------------------|
| 局部瓷砖铺贴 | 局部瓷砖铺贴【2小时】 | 200 |
| 壁纸铺贴施工 | 壁纸铺贴施工【2小时】 | 190 |
| … | 同文件内 8 条修缮类 | 已填 |

执行 `node seed_service_groups.js` 后，若库中已存在同 `title`+`category_id` 行则 **UPDATE** `sales_count`；否则 **INSERT** 并带上 `sales_count`。

## 4. 直约服务商默认四条 ↔ `merchant_strip_services_seed.json`

| JSON `title` | 前端原 `goodsTitle` | 建议 |
|--------------|---------------------|------|
| 金牌日常保洁 (2小时) | 同左 | 插入 `Services` 后，将 `sales_count_hint` 设大值保证进 `hot` 前四，或单独维护「首页横条」运营位表 |

**注意**：这四条与「房屋修缮」分组业务不同，需在主站指定 **`category_id`**（如「家政保洁」）后再执行 SQL/脚本插入；本仓库仅提供**内容数据**，不强制 `category_id`（因各环境分类主键不同）。

## 5. 直约技工 ↔ `workers_seed.json`

| JSON 字段 | 建议 `Workers` 表字段 | `GET core/workers` 返回字段（与 `worker-detail` 兼容） |
|-----------|----------------------|--------------------------------------------------------|
| name | `name` / `real_name` | `name` |
| service_count | `service_count` | `orders` 或 `service_count`（前端 `normalizeWorker` 已兼容） |
| region | `city` / `region` | `region` |
| gender | `gender` | `gender` |
| work_years | `work_years` | `exp` / `work_years` |
| resume | `resume` / `bio` | `desc` / `resume` |
| tags | JSON 列 `tags` | `tags` 数组 |
| — | `avatar_url`（上传后 URL） | 前端优先 `imgUrl(avatar_url)`，无则 `workerAvatarUrl(id)` |

`id_hint` 仅说明与旧前端假数据一致，**落库不要用固定主键**，除非与订单外键对齐。

## 6. 管家精选 ↔ `featured_goods_seed.json`

| JSON | 前端原 `marketList` | API `core/goods/featured` |
|------|---------------------|---------------------------|
| title | name | `goodsTitle` / `title` / `name` |
| price | price | `goodsRealPrice` / `price` |
| cover_image | image（经 images.xxx） | `mainPicture` / `cover_image` |

## 10. 如何导入（运维步骤）

1. **服务九类 + 热卖销量**  
   在含 `./src/models` 的社区后端根目录：  
   `node seed_service_groups.js`  
   脚本会合并 **`backend/seed-data/home-inner/service_groups_extra.json`**（已改 `seed_service_groups.js`）。

2. **Banner / 技工 / 精选商品 / 四条保洁**  
   当前仓库仅提供 **JSON + `seed_banners_example.sql` 模板**；请主站在迁移或管理端按映射写入。可将 `merchant_strip_services_seed.json` 导入逻辑并入 `seed_demo.js` 或独立 `node scripts/seed-home-inner-aux.js`（待主站补全模型后添加）。

3. **前端切换真实数据**  
   - `utils/config.js`：`useCuratedHomeHotList: false`  
   - `index.js`：Banner、`categoryList` 等逐步改为 `util.get('core/banners')` 等（见 `doc/首页与我的_服务域前后端联调需求.md`）。  
   - 假数据可删或保留为 **仅离线包无网兜底**（建议 `if (!config.useOfflineFallback)` 控制）。
