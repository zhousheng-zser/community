# 后端自动化测试（CW 全流程 E2E）

脚本路径：`backend/scripts/e2e-cw-fullflow.js`  
报告输出：`doc/cw测试结果/后端首页全流程回环测试报告_<时间戳>.md`

## npm scripts（`backend/package.json`）

| 命令 | 说明 |
|------|------|
| `npm test` / `npm run test:e2e:cw` | 全流程 E2E（含运营中台登录、**服务商运行中台**上架服务、邻里帮帮 5 类、异常流、多小区隔离） |
| `npm run simulate:home-chain` | **首页家修急事**假数据全链路：直约技工 / 待派单→运营指派 / 服务商打包（用户与履约方闭环） |
| `npm run migrate:sp-community` | `service_provider_profiles.community_id` 迁移 |
| `npm run migrate:sp-portal-accounts` | `service_provider_portal_accounts` 表（服务商运行中台登录） |
| `npm run lint` | `src/**/*.js` 语法校验（`node --check`） |
| `npm run typecheck` | 占位，成功退出 |
| `npm run e2e:home` | 旧版 `e2e-home-service-test.js` |

## 运行方式

在 **`backend` 目录** 且 **MySQL 可连**（与 `.env` 一致）时：

```bash
cd backend
npm test
```

仅连接已启动的 API（不拉起子进程）：

```bash
cd backend
E2E_EXTERNAL=1 E2E_BASE_URL=http://127.0.0.1:3001/api/v1 npm run test:e2e:cw
```

（请将端口与实际上一致；脚本内嵌子进程默认 **3099**。）

**运营中台（`admin` + Vite）**：代理默认指向 `127.0.0.1:3001`，须**先起 API** 再开页面，否则会 `ECONNREFUSED`。一键：`bash scripts/dev-admin-stack.sh`（仓库根目录）。

## 主测试小区（默认「上海合川路地铁站」）

种子数据标题/地址备注会带小区名；主流程用户 `users.community_id` 与技工/服务商档案默认对齐主小区。

| 环境变量 | 默认 | 说明 |
|----------|------|------|
| `E2E_COMMUNITY_LABEL` | `上海合川路地铁站` | 写入 `address_snapshot`、服务/类目标题等模拟文案 |
| `E2E_COMMUNITY_ID_MAIN` | `1` | 主测试小区 ID（`?community_id=`、下单等） |
| `E2E_COMMUNITY_ID_ALT` | `2` | 对照小区（多小区隔离用例） |

## 业务链条覆盖（与脚本步骤对应）

| 场景 | API / 说明 |
|------|------------|
| 运营中台登录 | `POST /auth/admin/login`（需配置 `ADMIN_USERNAME` / `ADMIN_PASSWORD`） |
| 技工入驻 | `POST /worker/apply` → `PUT /admin/worker-applications/:id` |
| 服务商入驻 | `POST /service-provider/apply` → `PUT /admin/service-provider-applications/:id` |
| **服务商运行中台** | `POST /admin/service-provider-portal-accounts` → `POST /service-provider-portal/login` → `GET .../dashboard` → `POST .../services`（上架服务）→ `GET .../services` |
| 下单技工服务（家修急事） | `GET /core/service-groups/urgent_fix` → `POST /service-orders`（直约技工）→ `mockPay` → 技工侧接单/打卡/证据/完成 → 用户 `confirm-complete` |
| 下单服务商打包单 | `POST /service-orders/bundle` → `mockPay` → `POST /service-provider/orders/:id/*`（小程序 JWT 服务商端） |
| 邻里帮帮（5 类） | `take` / `trash` / `pet` / `child` / `escort`：下单→支付→**管理端派单** 或 **技工抢单**（`GET /neighbor-assist/orders/pool` + `POST .../grab`）→接单→完成→DB 校验 |
| **商家后台（集市商品）** | 管理端建店/建账号/建商品 → `POST /merchant-portal/login` → `GET /market/merchant/goods` → `POST .../goods/:id/shelf` 上架 |
| **站内沟通（用户↔技工）** | `POST /messages/send`（双向）→ `GET /messages/conversations` → `GET /messages/history/:conversationId` |
| **运营客服监控** | `GET /admin/messages/overview`（会话量、消息数、未结 complaint_tickets） |
| **到家订单投诉** | `POST /service-orders/:id/complaint` → 表 `service_order_complaints` |
| **运营投诉工单** | `POST/GET /admin/complaint-tickets` → `PUT .../:id` 处理结案 |
| **意见反馈** | `POST /feedback/submit` |
| **小区管家** | 后端无独立管家角色/API；客服能力 = 私信 + 工单 + 订单投诉 + 运营精选等运营位（报告内有说明段） |

## CI 建议

`npm run lint` → `npm run typecheck` →（数据库就绪后）`npm test`。


该文档是否是对具体的功能的完整链条进行测试了的。具体一点说:“当客户下单某个技工服务后，应该测试下单是否成功，数据是否进入了数据库，是否该数据绑定到了对应的小区，是否正常支付了订单，该订单能否被对应技工接单，是否能建立对话信息，是否能在接单后正确规划路线(能查看，导出地址也行)，是否在点击上门打开拍照后，后台管理能查看到对应打卡数据，完成服务后是否能正常打卡拍照，客户点击确认完成后，是否支付金额能正常到账。是否能将对应金额显示在技工工作台（或者技工账号）的对应余额。” 我需要的是这样的完整的测试链路，不是只对每个单独的功能进行测试。
