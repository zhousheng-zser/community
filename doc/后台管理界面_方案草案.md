# 小程序后端管理网页 — 方案草案（待你确认）

> 本文档用于对齐「运营 / 管理员在 PC 浏览器里配置与审核小程序侧内容」的思路。你审阅后可指出增删改，再进入具体开发与接口设计。

---

## 1. 对你需求的理解（思路归纳）

- **使用者**：内部运营、店长或财务等角色，通过 **Web 管理端** 维护数据，**不**在小程序里改代码、改假数据。
- **目标**：把当前小程序里仍依赖 **本地 Mock、写死配置** 或可运营的内容，逐步变为 **后台可配、可审、可统计**；与现有 **`admin/`（Vue3 + Element Plus）** 工程自然衔接，而不是另起一套无关技术栈。
- **边界**：管理端 **只服务 B 端**；C 端用户仍只用小程序。敏感操作（提现、下架、删帖）需 **登录 + 角色权限 + 操作留痕**（可分阶段实现）。

## 3. 建议的信息架构（后台菜单 / 模块）

按 **业务域** 划分，便于分阶段交付；名称可按你产品习惯微调。

### 3.1 总览与账号

- **工作台 / 数据看板**：核心指标卡片（订单、用户、佣金、待审核数等）；后续可接图表（ECharts）。
- **登录与权限**：管理员账号、角色（运营 / 财务 / 超级管理员）；JWT 或 Session；与小程序用户体系 **分离**。

### 3.2 内容与营销（与小程序首页强相关）

- **惠民卡 · 京东联盟**  
  - 维护 **单表** `jd_benefit_goods` 对应字段：场景、SKU、标题、主图 URL、推广链接 `spread_url`、展示价、返利、排序、上下架。  
  - 能力：列表、搜索、新增/编辑、排序、上架/下架；可选「从 Excel 导入」后置需求。
- **惠民卡 · 拼多多 / 淘宝（若继续运营）**  
  - 若仍走「配置 + 接口转链」：可单独子菜单或合并为 **「联盟商品池（多平台）」**，按 `platform` 区分；**表结构需你确认是否也要单表化**（当前小程序侧多为 Mock + 预留接口）。
- **首页 / 核心运营位**（与 `doc` 中 core、banners、categories 等对齐）  
  - Banner、服务类目、热门服务等的 **增删改排序**（依赖现有或待补的 `GET/POST` 管理接口）。
- **本地好物 / 推客商品**  
  - 与文档中的 `shop_products`、推流、佣金、视频号直播位等对齐：**商品池、上下架、佣金比例、关联素材**。

### 3.3 交易与本地商业

- **本地集市**：店铺、商品、分类、营业状态；与 `market/*` 接口对齐。  
- **订单与售后**：订单列表、状态、退款/异常标记（按你现有订单模型裁剪）。  
- **地址 / 区域策略**（若运营需要）：与地址、集市半径策略相关的配置说明项。

### 3.4 社区与风控

- **帖子 / 评论**：列表、按分类/关键词筛选、屏蔽、删除（软删）、敏感操作日志。  
- **用户与举报**：用户列表简档、封禁/解封（若业务需要）；意见反馈查看与处理状态。

### 3.5 财务与结算

- **达人佣金 / 提现审核**：与现有 `Finance.vue` 一致方向；对接真实审核、打款状态回写。  
- **对账与导出**（可二期）：按日期导出订单与佣金流水。

### 3.6 系统

- **操作日志**（建议二期）：谁在何时改了哪条惠民卡商品、哪笔提现。  
- **文件上传**：商品图、Banner 等走统一上传接口 + OSS/本地存储策略（与线上一致）。

## 5. 技术路线（与现有仓库对齐）

- **前端**：延续 **`admin/`：Vue 3 + Vue Router + Pinia + Element Plus**；按模块拆 `views/`，公共表格/表单可抽组件。  
- **请求**：统一 `axios` 实例（已有 `request.js`），`baseURL` 对齐线上 `https://你的域名/api/v1` 或网关规则；拦截器带 **Admin Token**。  
- **后端**：在现有 Node 服务上增加 **`/api/v1/admin/*`** 前缀（推荐），与小程序 **`/api/v1/*`** 共用一套服务但 **路由与鉴权隔离**；惠民卡商品可用 **`/api/v1/admin/jd-benefit-goods`** CRUD，小程序只保留只读 **`/api/v1/jd/benefit/goods`**。  
- **安全**：管理接口 **必须鉴权**；生产环境 **HTTPS**；敏感配置（京东 PID 等）放环境变量，不进前端。

## 6. 分期实施建议（你可调整优先级）

| 阶段 | 范围 | 价值 |
|------|------|------|
| **一期** | 登录 + 惠民卡京东商品 CRUD（对接 `jd_benefit_goods`）+ 列表/排序/上下架 | 与当前小程序惠民卡京东 tab 立刻打通，去掉手工改库 |
| **二期** | Dashboard 真实指标；Goods 与线上推客商品 API 对齐；Finance 提现审核打通 | 运营与财务日常闭环 |
| **三期** | 首页 Banner/类目；本地集市店铺；社区审核 | 覆盖首页与社区运营 |
| **四期** | 操作日志、多角色权限、数据导出、多平台联盟统一后台 | 规模化与合规 |

## 7. 待你拍板的问题（审阅时请直接回复意见）

1. **管理端域名与部署**：是否与 API 同域反代（如 `https://api.xxx.com` + `https://admin.xxx.com`），还是开发期仅内网 IP？  
2. **账号体系**：是否已有 **独立管理员表**，还是复用某种企业微信 / 单点登录？  
3. **惠民卡多平台**：拼多多、淘宝是否也要 **和京东一样做后台单表维护**，还是短期仍只运营京东？  
4. **一期必须上的菜单**：除京东惠民卡外，是否强制包含 **Dashboard 真数据** 或 **商品池**？  
5. **权限模型**：是否需要「运营只能改内容、财务只能看提现」等 **细粒度角色**（一期可只做超级管理员）。

## 9. 一期已落地（实施备忘）

- **后端**（`backend/`）：`POST /api/v1/admin/login`（JWT）；`GET/POST/PUT/DELETE /api/v1/admin/jd-benefit-goods`（需 `Authorization: Bearer`）。环境变量见 `backend/.env.example`（`ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_JWT_SECRET`）。
- **管理端**（`admin/`）：`npm run dev`，浏览器打开 `http://localhost:5173/login`。开发环境 `VITE_API_BASE=/api/v1`，经 Vite 代理到本机 `3000`（见 `admin/vite.config.js`），**须同时**在 `backend` 执行 `npm start`。侧栏「惠民卡·京东商品」CRUD；登录后路由守卫校验 `admin_token`。
