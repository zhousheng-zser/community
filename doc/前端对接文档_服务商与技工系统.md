## 1. 环境准备

### 1.1 后端启动

```bash
cd backend
# 开发模式（跳过各类认证校验）
DEBUG_SKIP_AUTH=1 \
DEBUG_SERVICE_PROVIDER_PORTAL_LOGIN=1 \
DEBUG_SKIP_SP_PORTAL_TOKEN=1 \
DEBUG_MERCHANT_LOGIN=1 \
DEBUG_SKIP_MERCHANT_TOKEN=1 \
DEBUG_SKIP_WORKER_PORTAL_LOGIN=1 \
WORKER_PORTAL_SMS_CODE=123456 \
node src/index.js
```

### 1.2 前端启动

```bash
# 服务商工作台
cd service-provider-portal && npm run dev
# 技工工作台
cd worker-portal && npm run dev
# 商家后台
cd merchant-portal && npm run dev
# 运营后台
cd admin && npm run dev
```

### 1.3 默认端口

| 项目 | 默认端口 | API代理目标 |
|------|---------|------------|
| service-provider-portal | 5173 | http://localhost:3001 |
| worker-portal | 5174 | http://localhost:3001 |
| merchant-portal | 5175 | http://localhost:3001 |
| admin | 5176 | http://localhost:3001 |

## 2. 认证体系

### 2.1 Token 类型

| 工作台 | Token Key (localStorage) | 获取方式 | Payload 特征 |
|--------|-------------------------|---------|-------------|
| 服务商工作台 | `sp_portal_token` | `POST /service-provider-portal/login` | `{ portal: 'service_provider', profile_id, provider_user_id }` |
| 技工工作台 | `worker_portal_token` | `POST /worker-portal/login` | `{ id, openid, portal: 'worker' }` |
| 商家后台 | `merchant_portal_token` | `POST /merchant-portal/login` | `{ portal: 'merchant', shop_id }` |
| 运营后台 | `admin_token` | Admin 独立登录 | `{ admin: true, sub }` |

### 2.2 请求头格式

```
Authorization: Bearer <token>
```

### 2.3 调试模式（开发阶段）

| 环境变量 | 作用 |
|---------|------|
| `DEBUG_SKIP_AUTH=1` | 跳过用户JWT认证，使用默认用户 |
| `DEBUG_SERVICE_PROVIDER_PORTAL_LOGIN=1` | 跳过服务商登录密码校验 |
| `DEBUG_SKIP_SP_PORTAL_TOKEN=1` | 允许用户JWT直连服务商API |
| `DEBUG_MERCHANT_LOGIN=1` | 跳过商家登录密码校验 |
| `DEBUG_SKIP_MERCHANT_TOKEN=1` | 允许用户JWT直连商家API |
| `DEBUG_SKIP_WORKER_PORTAL_LOGIN=1` | 跳过技工登录验证码校验 |
| `WORKER_PORTAL_SMS_CODE=123456` | 设置固定验证码 |

## 3. 通用规范

### 3.1 响应格式

**成功:**
```json
{
  "errno": 0,
  "data": { ... }
}
```

**失败:**
```json
{
  "errno": 400,
  "errmsg": "错误描述"
}
```

> 注：Admin API 部分接口使用 `{ message: 'ok', data: ... }` 格式，详见各接口说明。

### 3.2 分页参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| page | int | 1 | 页码 |
| limit | int | 20 | 每页数量 |

**分页响应:**
```json
{
  "errno": 0,
  "data": {
    "list": [...],
    "total": 100,
    "page": 1,
    "limit": 20
  }
}
```

### 3.3 金额字段

所有金额字段返回为 **字符串**（如 `"128.00"`），避免 JavaScript 浮点精度问题。

## 4. 服务商工作台 API

**前缀**: `/api/v1/service-provider-portal`  
**认证**: `serviceProviderPortalAuthMiddleware` (Bearer `sp_portal_token`)

### 4.1 认证相关

#### POST /service-provider-portal/login
账号密码登录（独立端点，无需认证）。

**请求体:**
```json
{
  "username": "sp_demo",
  "password": "sp_demo123"
}
```

**响应:**
```json
{
  "errno": 0,
  "data": {
    "token": "eyJhbGciOiJIUzI1Ni...",
    "profile": { "id": 1, "shop_name": "晶洁家政", "user_id": 65, "community_id": 1 },
    "account": { "id": 1, "username": "sp_demo", "role": "owner" }
  }
}
```

> 调试模式 `DEBUG_SERVICE_PROVIDER_PORTAL_LOGIN=1` 时，username/password 可空，自动使用首个有效账号。

---

#### POST /service-provider-portal/token/exchange
用户JWT换取服务商门户Token。

**认证**: `authMiddleware` (用户JWT)

**响应:** 同 login

> 若门户账号不存在，自动创建（owner角色，随机密码）。

#### POST /worker-portal/login

**请求体:**

```json
  "service_title": "家电清洗"
```

---

#### GET /worker/service-orders/:id
订单详情。

**响应:** 同列表单条，额外包含 `buyer_user_id`, `buyer_name`, `buyer_phone`, `buyer_phone_masked`

接单。

**条件:** `status === 'pending_worker_accept'` 或 `status === 'dispatched'`

**响应:**
```json
{
  "errno": 0,
  "data": { "id": 88, "status": "in_service", "status_text": "服务中" }
}
```

---

#### POST /worker/service-orders/:id/reject
拒单。

**条件:** `status === 'dispatched'` 或 `status === 'pending_worker_accept'`

**请求体:**
```json
{ "reason": "距离太远，无法上门" }
```

> 拒单后订单状态回到 `paid_pending_dispatch`（已支付）或 `pending_pay`（未支付），`assigned_worker_id` 清空。

#### POST /worker/service-orders/:id/check-in
到达打卡。

**请求体:**
```json
{
  "latitude": 31.2304,
  "longitude": 121.4737,
  "accuracy": 10
}
```

> 技工端使用浏览器真实定位，服务商端当前使用硬编码坐标（开发联调用）。

---

#### POST /worker/service-orders/:id/evidence
上传留证照片。

**请求体:**
```json
{
  "kind": "before",
  "urls": ["https://example.com/before1.jpg"]
}
```

---

#### POST /worker/service-orders/:id/addon-request
加项申请。

**请求体:**
```json
{ "remark": "用户要求额外清洗空调滤网，加收50元" }
```

> 加项记录存储在 `fulfillment_meta.addon_requests` 数组中。

---

#### POST /worker/service-orders/:id/complete
完成服务。

**条件:** `status === 'in_service'`

**响应:**
```json
{
  "errno": 0,
  "data": { "id": 88, "status": "pending_user_confirm", "status_text": "待用户确认完成" }
}
```

> 若 `fulfillment_meta.await_user_confirm === false`，则直接变为 `completed`。

## 9. 订单状态机

### 9.1 服务订单状态定义

```js
const SERVICE_ORDER_STATUS_TEXT = {
  pending_pay:           '待支付',
  pending_accept:        '待服务商接单',
  pending_worker_accept: '待技工接单',
  paid_pending_dispatch: '待派单',
  dispatched:            '已派单',
  in_service:            '服务中',
  pending_user_confirm:  '待用户确认完成',
  completed:             '已完成',
  cancelled:             '已取消',
  closed:                '已关闭'
};
```

### 9.2 状态流转图

```
┌─────────────┐
│ pending_pay │◄──── 创建订单
└──────┬──────┘
       │ 支付成功
       ▼
┌─────────────────────────────────────────────────────────────┐
│ 支付后状态分支:                                              │
│ 1. 有 provider_user_id (直挂服务商) → pending_accept        │
│ 2. 有 assigned_worker_id (直约技工) → pending_worker_accept │
│ 3. 无服务商无技工 → paid_pending_dispatch                   │
└─────────────────────────────────────────────────────────────┘

【分支 1: 直挂服务商】
pending_accept ──► 服务商接单 ──► paid_pending_dispatch ──► 派单 ──► dispatched
                                                                    │
【分支 2: 直约技工】                                               ▼
pending_worker_accept ──► 技工接单 ──► dispatched ──► in_service
                                                      │
【分支 3: 平台派单】                                  ▼
paid_pending_dispatch ──► 派单 ──► dispatched ──► in_service
                                                    │
                                                    ▼
                                              in_service ──► 服务商/技工完成 ──► pending_user_confirm
                                                                                  │
                                                                                  ▼
                                                                            用户确认 ──► completed
```

### 9.3 各端可操作状态对照

| 状态 | 服务商端 | 技工端 | Admin端 | C端用户 |
|------|---------|--------|---------|--------|
| pending_accept | 接单/拒单 | — | — | — |
| pending_worker_accept | — | 接单/拒单 | — | — |
| paid_pending_dispatch | — | — | 派单 | — |
| dispatched | — | 接单/拒单/打卡 | — | — |
| in_service | 打卡/凭证/完成 | 打卡/凭证/加项/完成 | — | — |
| pending_user_confirm | — | — | — | 确认完成 |
| completed | — | — | — | 评价/投诉 |

## 11. 前端调用示例

### 11.1 Axios 封装（服务商工作台）

```js
// utils/request.js
import axios from 'axios'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE || '/api/v1',
  timeout: 30000
})

request.interceptors.request.use((config) => {
  const token = localStorage.getItem('sp_portal_token')
  if (token) config.headers.Authorization = 'Bearer ' + token
  return config
})

request.interceptors.response.use(
  (response) => {
    const d = response.data
    if (d && typeof d.errno === 'number' && d.errno !== 0) {
      return Promise.reject(new Error(d.errmsg || '请求失败'))
    }
    return d
  },
  (err) => {
    if (err.response && err.response.status === 401) {
      localStorage.removeItem('sp_portal_token')
      window.location.href = '/login'
    }
    return Promise.reject(err)
  }
)

export default request
```

### 11.2 调用示例

```js
import request from './utils/request'
```
