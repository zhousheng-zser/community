# 直约服务商 · 直约技工 — 首页名单接口规范

> **用途**：后端实现/对齐接口，保证首页「直约服务商」「直约技工」模块数据**全部来自服务端**。  
> **小程序 baseUrl**：`/api/v1`（见 `utils/config.js`）。  
> **响应总约定**：与项目统一；推荐 **`{ "errno": 0, "errmsg": "ok", "data": ... }`**；若暂无 `errno`，仅返回 **`{ "message": "ok", "data": ... }`** 且 **HTTP 200**，前端亦按成功解析（见 `utils/util.js`）。业务失败用 **`errno !== 0`**，勿单靠 HTTP 状态码。

---

## 1. 直约服务商（服务 SKU 列表）

### 1.1 当前前端调用

| 项 | 值 |
|----|-----|
| 方法 | `GET` |
| 路径 | **`/api/v1/core/services/hot`** |
| 鉴权 | 无 |
| Query | `limit`（可选，建议默认 10，最大 20）；`community_id`（可选，与小区内运营策略一致时传入，用于排序/过滤） |

### 1.2 `data` 形态（须兼容）

前端使用 **`utils/unwrapList`** 解析，支持以下任一：

- **`data` 为数组**：`[{ ... }, ...]`
- **`data` 为对象**：`{ "list": [ ... ], "total": n, "page": 1, "page_size": 20 }`（推荐分页类统一此形态）

首页仅取 **`list` 或数组的前 4 条** 展示在「直约服务商」卡片。

### 1.3 列表项字段（每条服务 / SKU）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | int | 是 | 服务主键；跳转 `pages/service/service?id={id}`，与 `GET /core/services/:id` 一致 |
| `title` | string | 是 | 服务标题；前端会去掉 `【…】` 片段作为列表主标题 |
| `description` | string | 否 | 副文案/摘要 |
| `price` | string/number | 是 | 展示价；前端格式化为两位小数 |
| `cover_image` | string | 否 | 主图 URL 或相对路径（如 `/uploads/...`）；空则前端用占位图 |
| `sales_count` | int | 否 | 累计销量；**建议提供**，供后续把副标题从「服务{id}单」改为真实销量（当前前端仍用占位 sub） |
| `sort_order` | int | 否 | 升序；同热度时二次排序 |
| `is_published` | tinyint | 否 | 仅返回上架 `1` |

### 1.4 业务规则（建议）

- 只返回 **可下单、已上架** 的服务。
- 排序：运营置顶（`sort_order`）→ 再按 **`sales_count` 降序** 或 **`updatedAt` 降序**（与产品一致即可）。
- 与 **小区热卖**、**全站热卖** 的数据源是否共用同一表由产品定；若需独立运营「直约服务商」位，可另增专用接口（见 §4）。

### 1.5 示例

**请求**

```http
GET /api/v1/core/services/hot?limit=10&community_id=1
```

**响应（推荐）**

```json
{
  "errno": 0,
  "data": {
    "list": [
      {
        "id": 31,
        "title": "金牌日常保洁【2小时】",
        "description": "含客厅、卧室、厨房、卫生间清洁",
        "price": "99.00",
        "cover_image": "https://example.com/cover.jpg",
        "sales_count": 312
      }
    ],
    "total": 48,
    "page": 1,
    "page_size": 10
  }
}
```

## 2. 直约技工（技工名单）

### 2.1 当前前端调用

| 项 | 值 |
|----|-----|
| 方法 | `GET` |
| 路径 | **`/api/v1/core/workers`** |
| 鉴权 | 无 |
| Query | `page`（默认 1）、`limit`（首页请求 **20**，列表页 **50**） |

### 2.2 `data` 形态（须兼容）

同样经 **`unwrapList`** 解析：

- **`data` 为数组**，或
- **`data`**：`{ "list": [ ... ], "total", "page", "page_size" | "limit" }`

首页横滑取 **`list` 前 5 条**；`pages/classify/classify` 取至多 **50 条**。

### 2.3 列表项字段（每名技工）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | int | 是 | 技工主键；跳转 `pages/worker-detail/worker-detail?id={id}`，与 `GET /core/workers/:id` 一致 |
| `name` | string | 是 | 展示名；无则前端用 `real_name`、`nickname` |
| `real_name` | string | 否 | 与 `name` 二选一或并存 |
| `nickname` | string | 否 | 同上 |
| `avatar_url` | string | 否 | **优先**头像；与 `avatar` 二选一 |
| `avatar` | string | 否 | 兼容字段 |
| `service_count` | int | 否 | 已服务单数；前端展示为「服务{n}单」；也可用 `serviceCount`、`order_count`（兼容） |
| `orders` | string | 否 | 已兼容旧形态，如 `"服务0单"` |
| `region` / `city` / `hometown` | string | 否 | 分类页展示地域 |
| `gender` | string | 否 | 如 `♂` / `♀` / `先生` / `女士` |
| `work_years` / `exp` | int | 否 | 工作年限 |
| `resume` / `desc` | string | 否 | 简介 |
| `tags` | string[] | 否 | 标签 |
| `status` | string | 否 | 仅返回可展示状态（如 `approved`） |

头像规则（前端已实现）：**有 `avatar_url`/`avatar` 则走 CDN/相对路径拼接；否则按 `id` 使用本地占位图**（`utils/workerApiMap.js`）。

### 2.4 业务规则（建议）

- 只返回 **审核通过、可接单展示** 的技工。
- 排序：`sort_order` 升序，或 **按 `service_count` 降序** / 入驻时间（与产品一致）。
- **`GET /api/v1/core/workers/:id`** 详情中的 **`id`、头像、姓名** 必须与列表一致，避免点进详情「换人」。

### 2.5 示例

**请求**

```http
GET /api/v1/core/workers?page=1&limit=20
```

**响应（推荐）**

```json
{
  "errno": 0,
  "data": {
    "list": [
      {
        "id": 7,
        "name": "张师傅",
        "real_name": "张师傅",
        "avatar_url": "https://example.com/a.jpg",
        "service_count": 128,
        "city": "成都",
        "gender": "♂",
        "work_years": 5,
        "resume": "擅长家政、维修",
        "tags": ["上门快", "好评多"]
      }
    ],
    "total": 100,
    "page": 1,
    "page_size": 20
  }
}
```

## 3. 与详情接口的 ID 空间

| 模块 | 列表 | 详情 |
|------|------|------|
| 直约服务商 | `GET .../core/services/hot` → `id` | `GET .../core/services/:id` |
| 直约技工 | `GET .../core/workers` → `id` | `GET .../core/workers/:id` |

详情接口字段需 **包含列表已展示的头像与姓名**，避免不一致。

---

## 4. 可选：独立首页位（若与「热卖」拆数据源）

若运营要求「直约服务商」**不等于**全站热卖榜数据源，可增加：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/v1/core/home/direct-services` | Query：`limit`、`community_id`；**`data.list` 字段与 §1.3 相同** |

技工同理可选：

| 方法 | 路径 |
|------|------|
| `GET` | `/api/v1/core/home/direct-workers` |

上线后由前端把首页请求从 `services/hot` / `workers` 切到上述路径即可；**字段表不变**。

---

## 5. 验收清单（后端自测）

- [ ] `GET core/services/hot`：`unwrapList` 能取出列表，`id/title/price/cover_image` 齐全，详情 `GET core/services/:id` 可打开。
- [ ] `GET core/workers`：返回 `list` 或数组；`id/name/avatar_url|avatar/service_count` 与 `GET core/workers/:id` 一致。
- [ ] 非法 `page`/`limit` 有边界（如 limit 最大 50）。
- [ ] 空列表时 HTTP 200，`list: []`。
