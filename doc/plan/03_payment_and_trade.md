# 第三阶段：微信支付与资金清算开发规划

小程序的命脉在于交易。因为涉及到真实的金钱流水和提佣分润，所以微信支付 API V3 的对接必须高度严谨与安全。

## 1. 资质及基础设施准备

1. **注册微信支付商户平台**：获取 `mch_id`。
2. **绑定小程序 AppID**：在商户号后台关联当前小程序的 AppID。
3. **API 证书配置**：这是极重要的秘钥！需要下载 `apiclient_key.pem` 和 `apiclient_cert.pem`，严格保存在 Node.js 后端服务器的安全隐蔽路径下（建议写进 `.env` 中读取）。绝不允许前端碰触证书。

## 2. 用户选品购买 -> 支付流程

整个商品到订单的交易流向：
1. **建单预扣**：用户在小程序商品详情点击“立即购买”。前端把商品 ID 和规格 ID 传给后端。后端效验库存，**生成一条 status="待支付" 的订单**，并锁定库存。
2. **统一下单**：后端拿着这笔钱数与 OpenID 向微信服务器请求 **商户统一下单 (JSAPI 下单)**。
3. **唤起收银台**：微信服务器将一串加密签名 (`timeStamp`, `nonceStr`, `package`, `paySign`) 回传给后端，后端转给前端小程序。
   - 小程序前端调用 `wx.requestPayment` 引出输入支付密码的密码框。
4. **支付回调 (Notify)**：支付成功后，微信服务器会主动通过外网 **POST** 请求您设定的如 `https://domain.com/api/payment/notify` 地址。
   - Node.js 在该回调中校验并验证签名防伪。若确认通过，将对应数据库 Order 状态改为 `已支付` 并解锁库存彻底发货。

## 3. 返佣清算体系设计

社区带货中，用户分享了“高佣商品”被其他人买了就会获得提成，这里的玩法有两个核心功能需要实现：

1. **分享关系参数追踪**
   - 达人 A 点击首页的商品卡，选择“分享赚 ￥XX”分发给朋友 B 或者发布带货视频。
   - 需要在生成的分享卡片或 `page` 路径上追加参数：`?goods_id=123&promoter_id=USER_A_ID`。
   - 好友 B 顺着链接一打开详情，**小程序立刻将当前购物状态归属于 A 所推荐**。
2. **交易完成佣金沉淀**与**提现链路（企业付款到零钱/转账发钱）**
   - 当上述订单结算且完成售后保护期后，触发分润，写入账单并给 A 的账户余额 `+￥10.00`。
   - A 请求提现。可以在后台人工点放款触发微信支付商户的 **“商家转账到零钱”接口（v3/transfer/batches）**，钱自动落入 A 微信的“我 -> 服务 -> 钱包 -> 零钱”。
