# “消息” 模块进度文档

## 整体进度概览
“消息”模块旨在实现系统广播、商家/客服、邻接私信的触达，提供完整的聊天互动体验。目前，**消息的列表展示（包含左滑删除高级交互）和后端接发收均已齐备，联调进度较好。**

## 前端开发进度 (联调完成)
- **消息会话列表 UI**：
  - 构建了简易大方的列表，包括头像展示（右上角带未读消息红点计数展示，处理了 “99+” 溢出UI）。
  - 展现消息发送者的昵称与最后一条消息概览、更新时间。涵盖对普通用户和“系统消息助手”的判定。
- **左滑删除动效**：
  - 通过精细的 `touchstart` 和 `touchmove` 手势监听，结合防误触（角度超过30度判定为非横移）算法，自己开发了一套平滑的左滑展开“删除”按钮的交互。
  - 点击删除后，采用先剔除本地前端数组元素再发送接口请求（`util.delete(...)`）的乐观策略，提升了 APP 流畅性。
- **进入对话**：
  - 点击会话卡片会携带特定的 `conversationId` 和 `peerId` 导航至 `/pages/chat/chat`，以便展示聊天气泡和实时收发消息。

## 后端开发进度 (对应模块完全具备)
根据 `API接口文档.md` 的第六部分：`/api/v1/messages` 接口群已经搭建完毕，必须带着登录 Authorization 才能正常握手：
- `GET /api/v1/messages/conversations` (获取我的会话列表) -> 已被前端成功调用。
- `GET /api/v1/messages/history/:conversationId` (获取具体聊天室内历史记录) -> 专供进入 chat 页面拉取。
- `POST /api/v1/messages/send` (发送私聊消息)。
- `DELETE /api/v1/messages/conversations/:conversationId` (软删除会话记录)。

## 联调及后续关键事项
1. **未读数与小红点**：前端获取了列表信息中的未读数。当小红点数字变化时，如果需要将底部 TabBar 关联渲染出数字标记，可以在此调用小程序的 TabBar 对应接口。
2. **长链接/轮询**：目前看来，列表获取是基于 `onShow` 的短链接拉动刷新。如果是完整的实时通信体验（如基于 WebSocket 或定时长轮询），后期可能需要对此页进行底层基座优化。
