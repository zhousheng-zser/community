# 第四阶段：订单与交易流程

## 1. 当前完成进度
根据实际业务需求，本阶段舍弃了复杂的购物车和状态流转，采用了**极简的“直接下单购买单一服务”**模型，极大提高了小程序的购买转化效率。

- [x] 创建 `Orders`（极简订单）表结构及模型。
- [x] 在 Sequelize 中配置 `Orders` 与 `Users` (买家) 以及 `Services` (服务商品) 的关联关系。
- [x] 实现了订单及交易核心接口：
  - `POST /api/v1/orders`：用户直接下单购买某项服务（自动拉取服务价格，状态为待支付）。
  - `GET /api/v1/orders/my`：获取当前登录用户的全部订单列表（带分页、包含购买的服务名称、图片及实付金额，按时间倒序排）。
  - `POST /api/v1/orders/:id/pay`：【模拟支付】专用于开发联调阶段的一键完成支付接口，可将订单状态从 `pending` 改为 `paid`。
- [x] 将对应的 API 路由 `orderRoutes` 挂载到了主服务，且全面开启 `JWT Token` 鉴权中间件保护。

## 2. API 接口指引 (测试或前端联调时使用)

*注意：本章节所有接口必须先调用 `POST /api/v1/auth/login` 获取 Token，并放置在请求头的 `Authorization: Bearer <Token>` 中。*

### 2.1 直接下单购买服务
**请求:** `POST http://localhost:3000/api/v1/orders`
**Body (JSON):**
```json
{
  "service_id": 1
}
```
*响应后会立刻生成一条记录，记录下购买人的ID、花了多少钱、买的什么服务，初始状态为 `pending`。*

### 2.2 查看我的订单列表
**请求:** `GET http://localhost:3000/api/v1/orders/my?page=1&limit=10`
*返回我的所有订单列表，以及关联的商品图片和标题，用于渲染“我的订单”页。*

### 2.3 模拟支付 (一键支付)
**请求:** `POST http://localhost:3000/api/v1/orders/{刚才生成的订单ID}/pay`
*前端可在“收银台”页面直接调用此接口，后端会更新此订单为 `paid` 已支付。*
