# 家集市店铺化 FE-BE 沟通纪要（后端视角·第 7 次）

（本次聚焦：**店铺地理信息、列表按距离筛选与排序、「商家」页素材、列表封面与评价数据**；**可直接转发后端/前端同事**。）

---

## 1. 背景与目标

- 家集市每个店铺需在数据库维护**可参与计算的地理位置**与**展示用地址文案**。
- 首页切换分类后，店铺列表应**仅展示用户位置方圆 X 公里内**的店铺，并支持**按距离由近到远排序**。
- **产品已定：X = 5 公里**（与前端 `radius_km`、后端默认配置对齐）。
- 首页「附近商家」筛选：**仅保留「综合排序」「距离优先」**，去掉「临工秒送」「商家自送」「重置筛选」。
- **列表卡片**：需展示**店铺封面图**（URL 存库、文件放服务器）。
- 店铺 **「评价」** Tab：需在后端维护**评价数据**（列表/聚合），供小程序展示（当前可为空态）。
- 店铺内 **「商家」** Tab：展示**地址、营业时间、联系电话**；**两张店铺照片**、**资质证照**均使用**服务器 URL**；**不再展示「联系人」**（前后端均下线该字段）。
- **虚构店铺阶段素材**：后端/运营可使用**网上已存在的图片 URL** 临时填充封面与「商家」页图片（**禁止 AI 生成图**）；下载后上传至自有服务器、数据库仅存**自有站点可访问路径**更安全，避免外链失效。

---

## 2. 关于 X（公里半径）

- 参考外卖类应用：常见 **3～5 公里** 高频区间（仅作参考）。
- **本期约定：X = 5 km**（`radius_km` 默认 5，与 `MARKET_SHOP_RADIUS_KM=5` 或等价配置一致）。

## 3. 数据库与字段（后端）

### 3.1 `market_shops`（或等价表）

| 字段 | 说明 |
|------|------|
| `address` | 文本地址（展示、搜索辅助） |
| `latitude` / `longitude` | 店铺坐标（建议 **GCJ-02**，与微信小程序 `wx.getLocation` 一致） |
| `business_hours` | 营业时间文案，如 `09:00~22:00` |
| `contact_phone` | 联系电话 |
| ~~`contact_name`~~ | **废弃**：不再维护；历史数据可保留但不返回给小程序 |
| **`cover_url`**（或 `list_cover_url`） | **首页/列表用封面图**（服务器路径或绝对 URL） |
| `facade_image` / `interior_image` | 两张「店铺照片」（商家 Tab） |
| `license_image` | 资质证照图 URL |
| `rating` / `sold_count` 等 | 已有则继续用于列表展示 |

**说明**：无经纬度的店铺是否出现在「距离筛选」结果中，由后端策略约定（建议：**不参与距离筛选**或排后）。

### 3.2 索引

- 对 `latitude/longitude` 建索引或空间索引，便于距离计算与分页。

### 3.3 评价（「评价」Tab / 图一）

- 需独立表或与订单关联的 **店铺评价** 数据（建议：`market_shop_reviews` 或等价），字段至少包含：`shop_id`、`user_id`（可选）、`rating`（1–5）、`content`、`images`（JSON 可选）、`created_at`；一期可仅提供 **列表接口 + 空列表**。
- **接口（建议）**：`GET /api/v1/market/shops/:shopId/reviews?page=&page_size=`，返回 `{ list, total }`；无数据时前端展示「暂时还没有用户评价」。

### 3.4 虚构数据填充素材（给后端的说明）

- 当前店铺多为示例数据，**封面、门面、内景、证照**可先用**网络现成图片**下载后上传至本服务器，**不要自行生成图片**；数据库中存**本站可访问的 URL**。
- 上线前替换为真实素材。

## 4. 接口约定

### 4.1 `GET /api/v1/market/shops`

**查询参数：**

| 参数 | 说明 |
|------|------|
| `category` | 分类编码（如 `AAAA`） |
| `page` / `page_size` | 分页 |
| `user_lat` / `user_lng` | 用户纬度/经度（GCJ-02） |
| `radius_km` | 可选；**默认 5**（与产品 X 一致） |
| `sort` | `comprehensive` / `distance` / 与现有枚举兼容；**距离优先**对应 `distance` |

**行为：**

- 当传入 **`user_lat` + `user_lng`**：仅返回距离 **≤ `radius_km`（默认 5）** 的店铺；`sort=distance` 时 **由近到远**。
- **返回 `list` 项**：含 **`cover_url`（或约定字段名）**、`distance_km`（有用户坐标时）、`rating`、`sold_count` 等。

### 4.2 `GET /api/v1/market/shops/:shopId`

**返回字段需包含：** `address`、`business_hours`、`contact_phone`、`cover_url`（可与列表一致）、`facade_image`、`interior_image`、`license_image`；**不包含**`contact_name`。

### 4.3 `GET /api/v1/market/shops/:shopId/reviews`（建议）

- 分页返回评价列表；暂无评价时 `list=[]`。

## 7. 联调验收用例（摘要）

1. **半径 5km** 内店铺出现，且 **距离优先** 时由近到远。
2. **综合排序** 与 **距离优先** 切换后列表与请求参数一致。
3. 列表卡片含 **封面**；**评价** Tab 有接口或空态。
4. 「商家」无联系人；图片均为可访问 URL。
