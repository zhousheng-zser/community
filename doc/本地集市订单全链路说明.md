# 本地集市订单全链路说明

## 1. 目标与范围

本文档描述当前仓库内“本地集市订单”的完整前后端逻辑，覆盖：

- 用户端：下单、支付、取消、退款、确认收货、查看物流、再来一单
- 商家端：订单列表、订单详情、接单/拒单/发货
- 消息模块：会话列表、历史消息、发送消息、订单会话确保
- 兼容性：旧接口路径与新接口路径并存

## 2. 核心状态机

### 2.1 订单状态 `order_status`

- `pending_payment`：待付款
- `pending_accept`：已付款待商家接单
- `pending_service`：商家备货中
- `pending_receipt`：配送中/待收货
- `completed`：已完成
- `cancelled`：已取消
- `refunded`：已退款

### 2.2 支付状态 `pay_status`

- `unpaid`：未支付
- `paid`：已支付
- `refund_pending`：退款处理中
- `refunded`：已退款

### 2.3 关键状态转换

- 用户创建订单：`pending_payment + unpaid`
- 模拟支付成功：`pending_payment -> pending_accept`，`unpaid -> paid`
- 商家接单：`pending_accept -> pending_service`
- 商家开始配送：`pending_service -> pending_receipt`
- 用户确认收货：`pending_receipt -> completed`
- 用户/商家取消并退款：进入 `cancelled/refunded`

## 3. 数据模型

### 3.1 订单域（新增）

- `MarketOrder` -> 表 `market_orders`

### 3.2 消息域（新增）

- `Conversation` -> 表 `conversations`

## 7.1 商家工作台会话功能补充说明

### 问题现象

- 在 `package-merchant/pages/merchant-orders/merchant-orders.js` 点击“联系买家”时，部分订单会提示“暂无法打开会话”。

### 根因

- 前端建会话接口 `POST /messages/order-conversation/ensure` 依赖 `buyer_user_id`。
- 商家订单列表数据中该字段不稳定，导致前端 `data-buyer-id` 为空，最终会话创建失败。

### 修复内容

- 后端补齐买家ID字段（商家订单列表与详情）：
  - 文件：`backend/src/modules/merchant/controllers/merchant.controller.js`
  - 增加返回：
    - `user_id`
    - `buyer_user_id`（等于 `user_id`）
- 前端补充买家ID兜底提取逻辑：
  - 文件：`utils/merchantOrderUi.js`
  - `buyerUserId` 提取顺序调整为：
    - `buyer_user_id` -> `buyer_id` -> `user_id` -> `user.id`

### 结果

- 商家工作台订单卡片“联系买家”可稳定创建会话并跳转聊天页。
- 即使后端未返回标准 `buyer_user_id`，前端也可通过兜底字段继续工作。
